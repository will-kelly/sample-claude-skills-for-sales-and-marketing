# Before-and-after ledger

The most common mistake in measuring AI tools is forgetting to measure before. Once the tool ships, nobody remembers how long the old way took, and "saves hours a week" becomes a number someone made up in a slide.

This skill makes the baseline part of the build and keeps the claims honest.

## When to use

- At kickoff, before anything ships
- Two to four weeks after release
- Before any results readout

## Three kinds of effect

Pick the one or two that actually apply. Don't force all three.

**Time saved.** Minutes per instance, times instances per week. Measure on real work, not a demo.

**Quality.** Agreed rubric, scored blind where possible. Examples for sales development: personalization that references something real about the account, correct ICP fit, messaging that matches current positioning, fewer manager rewrites.

**Work made possible.** Things the team couldn't do before at any reasonable cost: researching every account in a territory instead of the top 20, same-day follow-up on every inbound. Count the new work, and say what it led to.

## Baseline capture

Before shipping:

1. Pick three to five reps, mixed tenure.
2. Time the workflow on real tasks. Light-touch is fine: have them note start and stop.
3. Save three sample outputs per rep.
4. Have a manager score the samples on the agreed rubric.
5. Note the current downstream signal if there is one (reply rate, meetings booked, rework requests), and note that it has other causes.

## After capture

Repeat the same steps with the same reps where you can. Add:

- Adoption: how many of the intended users used it in the last week
- Where people stopped using it, and why (ask them)

## Honesty rules

Every number in the ledger gets one of three labels:

- **Measured.** Observed directly.
- **Estimated.** Extrapolated from a measured sample. Show the math.
- **Reported.** Someone said so. Useful, but say who.

Never present an estimated or reported number as measured. Never extrapolate a pilot of four reps to the whole org without saying that's what you did. If the result is small or mixed, write that down. A tool that saved ten minutes a day and nobody's using it is a finding.

## Output

A ledger table per build: metric, before, after, label, sample size, notes. Followed by two sentences in plain language: what changed, and what you'd want to know next.
